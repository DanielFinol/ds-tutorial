Warehouse tables are the easy case. Sooner or later someone emails you a spreadsheet export and asks for numbers by Friday. This lesson is one such file, cleaned step by step. The order of operations is the skill: **look, fix structure, fix values, validate, document**.

You'll write each step as a small function that takes a DataFrame and returns a new one. That keeps every step testable and re-runnable, and at the end the steps chain into one pipeline.

> Dropping *exact* duplicates is safe. If rows shared an `order_id` but differed elsewhere, you'd have a real conflict to investigate and to raise with the data owner, not something to "fix" with `keep="first"`.

## 3. Categorical text

**3.** Complete `clean_labels`. For `status`: trim whitespace, lower-case, and turn `"n/a"` into a real missing value. For `country`: map every spelling to one of the five codes `US`, `UK`, `DE`, `FR`, `CA`.

Write the country mapping explicitly. An explicit map leaves unknown spellings missing, so it fails loudly when a new one appears next month; clever fuzzy matching fails silently.

## 5. Implausible values

The summary shows a maximum far above the 75th percentile. Look at the extremes before deciding anything.

<PyCell code={`

Six orders are roughly a hundred times too large and have no decimal part: they were logged in **cents**. This is a fixable unit error, not an outlier to delete. You confirm with Dana, then fix it with a rule you can state in one sentence.

**5.** Complete `fix_cents`: divide `total` by 100 where it exceeds 3,000 (well above any genuine order here), and record which rows you changed in a boolean column `total_was_cents`.

## 6. Dates in three formats

<PyCell code={`
print(step5["order_date"].sample(6, random_state=1).tolist())
`} />

Letting a parser guess is how 5 March becomes 3 May. `22/12/2024` is unambiguous, `05/03/2024` is not, and a guessing parser will happily pick a different reading per row. Parse each known format **explicitly** and combine.

**6.** Complete `parse_dates` so `order_date` is a proper datetime column with nothing missing. The three formats are `%Y-%m-%d %H:%M:%S`, `%d/%m/%Y %H:%M` and `%b %d, %Y`.

<PyCell
  code={`
def parse_dates(df: pd.DataFrame) -> pd.DataFrame:
    df = df.copy()
    iso = pd.to_datetime(df["order_date"], format="%Y-%m-%d %H:%M:%S", errors="coerce")
    # parse the other two formats the same way, then combine with .fillna(...)
    df["order_date"] = iso
    return df

step6 = parse_dates(step5)
print(step6["order_date"].dtype, step6["order_date"].isna().sum(), "missing")
`}
  check={`
_o = parse_dates(fix_cents(parse_numbers(clean_labels(drop_bad_rows(clean_columns(raw))))))
assert pd.api.types.is_datetime64_any_dtype(_o["order_date"]), "order_date should be a datetime column"
assert _o["order_date"].notna().all(), f"{_o['order_date'].isna().sum()} dates failed to parse"
_t = dsw.load("orders").set_index("order_id")["order_ts"].reindex(_o["order_id"]).dt.normalize().to_numpy()
_bad = _o["order_date"].dt.normalize().to_numpy() != _t
assert not _bad.any(), f"{_bad.sum()} dates are wrong (day and month swapped?), e.g. order {_o.loc[_bad, 'order_id'].iloc[0]}"
`}
  hint="`dmy = pd.to_datetime(df['order_date'], format='%d/%m/%Y %H:%M', errors='coerce')`, likewise for `'%b %d, %Y'`, then `iso.fillna(dmy).fillna(text)`."
  solution={`
def parse_dates(df: pd.DataFrame) -> pd.DataFrame:
    df = df.copy()
    iso = pd.to_datetime(df["order_date"], format="%Y-%m-%d %H:%M:%S", errors="coerce")
    dmy = pd.to_datetime(df["order_date"], format="%d/%m/%Y %H:%M", errors="coerce")
    text = pd.to_datetime(df["order_date"], format="%b %d, %Y", errors="coerce")
    df["order_date"] = iso.fillna(dmy).fillna(text)
    return df

step6 = parse_dates(step5)
print(step6["order_date"].dtype, step6["order_date"].isna().sum(), "missing")
`}

## 7. One pipeline, permanent checks

The six functions chain into a pipeline you can re-run on next month's file:

<PyCell code={`
def clean_orders(raw: pd.DataFrame) -> pd.DataFrame:
    return (
        raw.pipe(clean_columns)
        .pipe(drop_bad_rows)
        .pipe(clean_labels)
        .pipe(parse_numbers)
        .pipe(fix_cents)
        .pipe(parse_dates)
    )

df = clean_orders(raw)
print(df.dtypes)
`} />

Everything you verified by eye should also be code, so that next month's export is checked in a second. At work this is a **data contract**: rules the table must satisfy, run automatically (with tools such as pandera, Great Expectations or dbt tests). The core idea fits in one function.

**7.** Complete `validate_orders(df)`, which returns a **list of problem descriptions** (an empty list means the table is valid). It must detect at least: duplicated `order_id`, QA orders (`customer_id` 0), statuses outside `completed`/`cancelled`/`refunded` (missing is allowed), and totals that are zero or negative (missing is allowed).

<PyCell
  code={`
def validate_orders(df: pd.DataFrame) -> list[str]:
    problems = []
    if df["order_id"].duplicated().any():
        problems.append(f"{df['order_id'].duplicated().sum()} duplicated order_id")
    # add the other rules
    return problems

validate_orders(df)
`}
  check={`
_c = parse_dates(fix_cents(parse_numbers(clean_labels(drop_bad_rows(clean_columns(raw))))))
assert validate_orders(_c) == [], f"the cleaned table should pass, got {validate_orders(_c)}"
_b = _c.copy(); _b.loc[_b.index[0], "customer_id"] = 0
assert validate_orders(_b), "a QA order (customer_id == 0) was not detected"
_b = _c.copy(); _b.loc[_b.index[0], "status"] = "shipped"
assert validate_orders(_b), "an unknown status ('shipped') was not detected"
_b = _c.copy(); _b.loc[_b.index[0], "total"] = -5.0
assert validate_orders(_b), "a negative total was not detected"
assert validate_orders(pd.concat([_c, _c.head(1)])), "a duplicated order_id was not detected"
assert len(validate_orders(clean_columns(raw))) >= 3, "the raw export should fail at least three rules"
`}
  hint="For each rule build a boolean mask of bad rows and append a message if `mask.any()`. Statuses: `~df['status'].isin([...]) & df['status'].notna()`. Totals: `pd.to_numeric(df['total'], errors='coerce') <= 0`."
  solution={`
def validate_orders(df: pd.DataFrame) -> list[str]:
    problems = []
    if df["order_id"].duplicated().any():
        problems.append(f"{df['order_id'].duplicated().sum()} duplicated order_id")
    qa = df["customer_id"] == 0
    if qa.any():
        problems.append(f"{qa.sum()} QA orders (customer_id == 0)")
    bad_status = ~df["status"].isin(["completed", "cancelled", "refunded"]) & df["status"].notna()
    if bad_status.any():
        problems.append(f"{bad_status.sum()} rows with unknown status, e.g. {sorted(df.loc[bad_status, 'status'].unique())[:3]}")
    bad_total = pd.to_numeric(df["total"], errors="coerce") <= 0
    if bad_total.any():
        problems.append(f"{bad_total.sum()} rows with total <= 0")
    return problems

validate_orders(df)
`}

## 8. Reconcile and report

Cleaning is finished when the result agrees with an independent source and you've written down what you did. Missing values that remain are **reported, not invented**: you don't fill 25 blank totals with the mean and call it revenue.

In your project, declare the same rules with **pandera**, the most common validation library for DataFrames:

```python
import pandas as pd
import pandera.pandas as pa

orders_schema = pa.DataFrameSchema(
    {
        "order_id": pa.Column(int, unique=True),
        "customer_id": pa.Column(int, pa.Check.gt(0)),
        "order_date": pa.Column("datetime64[ns]"),
        "status": pa.Column(str, pa.Check.isin(["completed", "cancelled", "refunded"]), nullable=True),
        "country": pa.Column(str, pa.Check.isin(["US", "UK", "DE", "FR", "CA"])),
        "discount_pct": pa.Column(int, pa.Check.isin([0, 10, 20, 30])),
        "total": pa.Column(float, pa.Check.gt(0), nullable=True),
    },
    strict=False,
)

clean = pd.read_parquet("data/orders_export_clean.parquet")   # written by your clean_orders()
orders_schema.validate(clean, lazy=True)   # lazy=True reports every failure at once
```

Then break the data on purpose (set one status to `"shipped"`) and read the error report. Put the schema in a module, call `validate` at the top of every pipeline that reads this file, and bad data stops at the door.
