Gradient-boosted trees are the default strong model for tabular data in industry: they handle mixed scales, missing values and interactions with almost no preprocessing. They also overfit readily and have a dozen knobs. This lesson is the working routine: **fit, check the gap, regularise, tune, interpret, compare with the baseline**.

The setup recreates the churn project from the previous lesson: train on the 1 April snapshot, test out-of-time on 1 July.

<PyCell code={`
import dsw
import numpy as np
import pandas as pd
from sklearn.metrics import roc_auc_score

train_raw, test_raw = dsw.churn_snapshot("2024-04-01"), dsw.churn_snapshot("2024-07-01")
y_train, y_test = train_raw["churned"], test_raw["churned"]

def prepare(df: pd.DataFrame) -> pd.DataFrame:
    """Model inputs for tree models: drop ids/label, add domain features, mark categoricals."""
    X = df.drop(columns=["customer_id", "churned"]).copy()
    X["avg_gap_days"] = (X["tenure_days"] - X["recency_days"]).clip(lower=1) / X["orders_total"]
    X["recency_ratio"] = X["recency_days"] / X["avg_gap_days"]
    for col in ["channel", "device", "country"]:
        X[col] = X[col].astype("category")
    return X

X_train, X_test = prepare(train_raw), prepare(test_raw)
print(X_train.shape, "missing values:", int(X_train.isna().sum().sum()))
`} />

## Regularise

The knobs that matter, in order of usefulness:

| Parameter | Effect | Typical range |
| --- | --- | --- |
| `learning_rate` | smaller steps, needs more trees, generalises better | 0.02 to 0.1 |
| `max_iter` + `early_stopping` | stop adding trees when a held-out score stops improving | up to 1,000 |
| `max_depth` / `max_leaf_nodes` | simpler trees | depth 2 to 6 |
| `min_samples_leaf` | no leaf built on a handful of rows | 20 to 200 |
| `l2_regularization` | shrinks leaf values | 0 to 10 |

**2.** Fit `gbm_reg` with `learning_rate=0.05`, `max_depth=3`, `min_samples_leaf=40`, `max_iter=500`, and early stopping on a 20% validation split (`early_stopping=True`, `validation_fraction=0.2`), keeping `categorical_features="from_dtype"` and `random_state=0`. Store its test AUC in `auc_reg`.

## Tune with cross-validation, never with the test set

Hand-picked values are a starting point. To search properly, score candidates by **cross-validation on the training data** and touch the test snapshot once, at the end. Random search covers a wide space cheaply.

## What did it learn?

Never ship a model whose behaviour you haven't inspected. **Permutation importance** shuffles one feature at a time on held-out data and measures how much the score drops. Unlike built-in "gain" importances, it reflects what the model needs for *new* data.

## Decide

On a few thousand rows with mostly smooth relationships, well-regularised boosting and logistic regression finish within about a hundredth of each other. That is a normal result, and a useful one: the differences are smaller than the noise between test periods, so the choice should be made on **cost of ownership**. The linear model is easier to explain, debug and monitor. Boosting earns its place when there is more data, strong interactions, or many messy features, and you now know how to find out which case you're in.

<Lab title="Explain predictions with SHAP; tune with Optuna" time="20 min">

Two tools you'll meet on most teams, neither available in the browser:

```bash
uv add shap optuna lightgbm
```

**SHAP** attributes each individual prediction to features, the standard answer to "why did *this* customer score 0.9?":

```python
import shap

explainer = shap.TreeExplainer(lgbm)
values = explainer(X_test)
shap.plots.beeswarm(values)        # global view: which features push risk up or down
shap.plots.waterfall(values[0])    # one customer: the reasons behind their score
```

**Optuna** replaces random search with a guided one and prunes hopeless trials early:

```python
import optuna
from sklearn.model_selection import cross_val_score

def objective(trial):
    model = lgb.LGBMClassifier(
        n_estimators=300, verbose=-1, random_state=0,
        learning_rate=trial.suggest_float("learning_rate", 0.01, 0.2, log=True),
        num_leaves=trial.suggest_int("num_leaves", 4, 32),
        min_child_samples=trial.suggest_int("min_child_samples", 10, 200),
        reg_lambda=trial.suggest_float("reg_lambda", 1e-3, 10, log=True),
    )
    return cross_val_score(model, X_train, y_train, cv=3, scoring="roc_auc").mean()

study = optuna.create_study(direction="maximize")
study.optimize(objective, n_trials=40)
print(study.best_value, study.best_params)
```

Compare the tuned test AUC with the table above. If forty trials buy you less than the gap between two test periods, you have your answer about where to spend the next day of work.
