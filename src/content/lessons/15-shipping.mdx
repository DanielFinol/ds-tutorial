A model in a notebook has delivered nothing. In the average workplace "production" rarely means a low-latency service; it usually means a **scheduled batch job**: every Monday, score all active customers and write a table that the CRM tool reads. This lesson builds that job's core, and the monitoring that tells you when to stop trusting it.

## 2. The scoring job

The scoring function is the contract between you and the people who use the scores. It must **refuse bad input loudly** rather than produce plausible garbage, and its output must carry enough metadata to trace any number back to a model and a date.

## 3. Monitoring: has the input changed?

Models fail quietly. Nobody gets an error when an upstream team changes a unit, a tracking event stops firing, or the customer mix shifts; the scores just get worse. True outcomes arrive 90 days late here, so the first line of defence is watching the **inputs**.

The standard drift measure in industry is the **Population Stability Index** (PSI): bin a feature using the training data's quantiles, then compare the share of rows per bin between training and now.

`PSI = Σ (actual% − expected%) × ln(actual% / expected%)`

Rule of thumb: below 0.1 stable, 0.1 to 0.2 worth a look, above 0.2 investigate before trusting the scores.

**2.** Implement `psi(expected, actual, bins=10)` for numeric Series. Use bin edges at the quantiles of `expected` (`np.quantile(expected, np.linspace(0, 1, bins + 1))`), de-duplicate the edges, widen the outer edges to ±infinity, ignore missing values, and floor each share at `1e-4` to avoid dividing by zero.

def psi(expected: pd.Series, actual: pd.Series, bins: int = 10) -> float:
    expected, actual = expected.dropna().to_numpy(dtype=float), actual.dropna().to_numpy(dtype=float)
    edges = np.unique(np.quantile(expected, np.linspace(0, 1, bins + 1)))
    edges[0], edges[-1] = -np.inf, np.inf
    e = np.clip(np.histogram(expected, edges)[0] / len(expected), 1e-4, None)

## 4. A drift report that raises alerts

  hint="Per column: `m_ref, m_cur = reference[col].isna().mean(), current[col].isna().mean()`; `value = psi(reference[col], current[col]) if current[col].notna().any() else float('nan')`; status is 'alert' if `value >= 0.2 or abs(m_cur - m_ref) > 0.1`, 'watch' if `value >= 0.1`, else 'ok'. Cast booleans with `.astype(float)` before calling psi."
  solution={`
def drift_report(reference: pd.DataFrame, current: pd.DataFrame, features: list[str]) -> pd.DataFrame:
    rows = {}
    for col in features:
        ref, cur = reference[col].astype(float), current[col].astype(float)
        m_ref, m_cur = ref.isna().mean(), cur.isna().mean()
        value = psi(ref, cur) if cur.notna().any() else float("nan")
        if value >= 0.2 or abs(m_cur - m_ref) > 0.1:
            status = "alert"
        elif value >= 0.1:
            status = "watch"
        else:
            status = "ok"
        rows[col] = {"psi": value, "missing_ref": m_ref, "missing_cur": m_cur, "status": status}
    return pd.DataFrame(rows).T.sort_values("psi", ascending=False)

report = drift_report(train, incoming, NUMERIC)
report[report["status"] != "ok"]
`}

Wire it into the job as a **gate**: if any feature is in alert, do not publish scores; notify the owner instead. A late campaign is an inconvenience. A campaign aimed at the wrong ten thousand customers costs money and trust.

<PyCell code={`
def run_scoring_job(snapshot: pd.DataFrame, scored_at: str) -> str:
    report = drift_report(train, snapshot, NUMERIC)
    alerts = report.index[report["status"] == "alert"].tolist()
    if alerts:
        return f"[{scored_at}] BLOCKED: drift alert on {alerts}. Scores not published; owner notified."
    scores = score_customers(snapshot, loaded, scored_at=scored_at)
    scores.to_parquet(f"scores/scored_at={scored_at}.parquet", index=False)
    return f"[{scored_at}] OK: {len(scores):,} customers scored, mean risk {scores['p_churn'].mean():.3f}"

print(run_scoring_job(dsw.churn_snapshot("2024-10-01"), "2024-10-01"))
print(run_scoring_job(incoming, "2024-10-08"))

## 5. Close the loop when outcomes arrive

Input monitoring is early warning. The real verdict comes when labels mature: 90 days after each scoring run you can compute how the model actually did, from the scores you archived.

<PyCell code={`
from sklearn.metrics import roc_auc_score

rows = []
for cutoff in ["2024-07-01", "2024-08-01", "2024-09-01"]:
    archived = pd.read_parquet(f"scores/scored_at={cutoff}.parquet")
    outcome = dsw.churn_snapshot(cutoff)[["customer_id", "churned"]]          # known 90 days later
    joined = archived.merge(outcome, on="customer_id", validate="one_to_one")
    top = joined[joined["risk_decile"] == 1]
    rows.append({"scored_at": cutoff, "auc": roc_auc_score(joined["churned"], joined["p_churn"]),
                 "predicted_rate": joined["p_churn"].mean(), "actual_rate": joined["churned"].mean(), "top_decile_precision": top["churned"].mean()})
pd.DataFrame(rows).set_index("scored_at").round(3)
`} />

Put those three numbers on a small dashboard with thresholds agreed in advance (for example: retrain if AUC falls below 0.74 or predicted and actual rates differ by more than five points for two months running). "Retrain when it looks bad" is not a policy; a threshold someone signed off is.

<Lab title="Make it a command-line job and schedule it" time="20 min">

Put the scoring logic in your `bramble` package and give it an entry point that takes the run date as an argument, so any run can be repeated for any date:

```python
# src/bramble/score.py
import argparse, logging
import joblib, pandas as pd
from bramble.scoring import score_customers, drift_report, build_snapshot   # your functions

logging.basicConfig(level=logging.INFO, format="%(asctime)s %(levelname)s %(message)s")
log = logging.getLogger("churn-scoring")

def main() -> int:
    parser = argparse.ArgumentParser()
    parser.add_argument("--date", required=True, help="scoring date, YYYY-MM-DD")
    parser.add_argument("--model", default="churn_model.joblib")
    parser.add_argument("--out", default="scores")
    args = parser.parse_args()

    bundle = joblib.load(args.model)
    snapshot = build_snapshot(args.date)
    report = drift_report(bundle["reference"], snapshot, bundle["numeric_features"])
    alerts = report.index[report["status"] == "alert"].tolist()
    if alerts:
        log.error("drift alert on %s: scores not published", alerts)
        return 1                                   # non-zero exit code = the scheduler marks the run as failed
    scores = score_customers(snapshot, bundle, scored_at=args.date)
    scores.to_parquet(f"{args.out}/scored_at={args.date}.parquet", index=False)
    log.info("scored %d customers, mean risk %.3f", len(scores), scores["p_churn"].mean())
    return 0

if __name__ == "__main__":
    raise SystemExit(main())
```

```python
# src/bramble/api.py
import joblib
import pandas as pd
from fastapi import FastAPI
from pydantic import BaseModel, Field

bundle = joblib.load("churn_model.joblib")
app = FastAPI(title="Churn risk")

class Customer(BaseModel):
    tenure_days: int = Field(ge=0)
    recency_days: int = Field(ge=0)
    orders_total: int = Field(ge=1)
    orders_90d: float = 0
    orders_365d: float = 0
    spend_90d: float = 0
    spend_365d: float = 0
    avg_order_value: float
    discount_share: float = Field(ge=0, le=1)
    refund_rate: float = Field(ge=0, le=1)
    tickets_180d: float = 0
    neg_tickets_180d: float = 0
    min_csat_180d: float | None = None
    age: float | None = None
    plus_member: bool
    channel: str
    device: str
    country: str

@app.get("/health")
def health():
    return {"status": "ok", "model_version": bundle["model_version"]}

@app.post("/score")
def score(customer: Customer):
    row = pd.DataFrame([customer.model_dump()])[bundle["features"]]
    return {"p_churn": float(bundle["model"].predict_proba(row)[0, 1]), "model_version": bundle["model_version"]}
```
