## 3. The baseline comes first

The **seasonal-naive** forecast repeats the last observed week. It costs nothing, is often hard to beat, and tells you what "good" means for this series. For the error, use **WAPE** (total absolute error divided by total actual units): unlike MAPE it is stable when some days are small, and "we're off by 15% of volume" is something Sam can use.

<PyCell code={`
def wape(actual, predicted) -> float:
    actual, predicted = np.asarray(actual, dtype=float), np.asarray(predicted, dtype=float)
    return np.abs(actual - predicted).sum() / actual.sum()

HORIZON = 28
train_y, test_y = y.iloc[:-HORIZON], y.iloc[-HORIZON:]
print("train:", train_y.index.min().date(), "to", train_y.index.max().date(), "| test:", test_y.index.min().date(), "to", test_y.index.max().date())
`} />

## 4. A feature-based model

The workhorse approach in industry treats forecasting as regression on **calendar features, known-in-advance drivers and lagged values**. One rule decides which lags are legal: to forecast 28 days ahead in one go, a feature for day *t* may only use data from day *t − 28* or earlier. Anything more recent is leakage, because you won't have it when you make the forecast.

**3.** Complete `make_features(df)`. It receives the daily Kitchen frame (columns `units`, `on_promo`) and returns a DataFrame with the same index and these columns: `dow` (day of week), `month`, `on_promo` (as 0/1; the promo calendar is planned ahead, so it is known), `lag_28`, `lag_35`, `lag_364` (units that many days earlier) and `roll_28_7` (mean of the 7 days ending 28 days earlier).

<PyCell
  code={`
def make_features(df: pd.DataFrame) -> pd.DataFrame:
    X = pd.DataFrame(index=df.index)
    X["dow"] = df.index.dayofweek
    X["month"] = df.index.month
    X["on_promo"] = df["on_promo"].astype(int)
    # lag_28, lag_35, lag_364 and roll_28_7
    return X

X = make_features(kitchen)
X.tail(3)

  hint="`X['lag_28'] = df['units'].shift(28)` and likewise for 35 and 364; `X['roll_28_7'] = df['units'].shift(28).rolling(7).mean()`."
  solution={`
def make_features(df: pd.DataFrame) -> pd.DataFrame:
    X = pd.DataFrame(index=df.index)
    X["dow"] = df.index.dayofweek
    X["month"] = df.index.month
    X["on_promo"] = df["on_promo"].astype(int)
    for k in (28, 35, 364):
        X[f"lag_{k}"] = df["units"].shift(k)
    X["roll_28_7"] = df["units"].shift(28).rolling(7).mean()
    return X

X = make_features(kitchen)
X.tail(3)
`}
/>

Gradient boosting with a Poisson loss suits count data. The first 364 rows have no year-ago lag, so training starts after them.

<PyCell code={`
from sklearn.ensemble import HistGradientBoostingRegressor

def fit_predict(train_end, horizon=HORIZON):
    """Train on data before train_end and forecast the following horizon days."""
    train_end = pd.Timestamp(train_end)
    fit_rows = (X.index < train_end) & X["lag_364"].notna()
    test_rows = (X.index >= train_end) & (X.index < train_end + pd.Timedelta(days=horizon))
    model = HistGradientBoostingRegressor(loss="poisson", learning_rate=0.05, max_iter=300, max_depth=4, random_state=0)
    model.fit(X[fit_rows], y[fit_rows])
    return pd.Series(model.predict(X[test_rows]), index=X.index[test_rows])

pred = fit_predict(test_y.index[0])
print(f"seasonal naive {wape(test_y, naive):.1%}   boosted model {wape(test_y, pred):.1%}")

ax = y.iloc[-70:].plot(label="actual", figsize=(9, 3.2))
naive.plot(ax=ax, label="seasonal naive", ls=":")
pred.plot(ax=ax, label="model")
ax.axvline(test_y.index[0], color="grey", lw=1)
ax.set_xlabel("")
ax.legend();
`} />

## 5. Backtest: one test window proves nothing

A single holdout month can flatter or punish a model by luck. A **rolling-origin backtest** repeats the exercise at several past dates, always training only on data before the forecast start.

**4.** Backtest the six 28-day windows starting at the dates in `starts`. For each, compute the WAPE of the seasonal-naive forecast (last 7 days before the start, repeated) and of `fit_predict(start)`. Store the results in `bt`: a DataFrame indexed by start date with columns `naive` and `model`.

The model wins on average, but not in every window. That's the realistic picture to report: *"about 16% error on a typical month against 21% for the naive method, ranging from 13% to 20%."* Had you looked at one window only, you could have concluded anything.

## 6. Give a range, not a number

Sam's second question was "how wrong could it be?" Warehouse staffing should be planned against a high-demand scenario, not the average. Train the same model with a **quantile loss** to forecast the 10th and 90th percentiles directly.

<PyCell code={`
def fit_quantile(q, train_end):
    train_end = pd.Timestamp(train_end)
    fit_rows = (X.index < train_end) & X["lag_364"].notna()
    test_rows = (X.index >= train_end) & (X.index < train_end + pd.Timedelta(days=HORIZON))
    m = HistGradientBoostingRegressor(loss="quantile", quantile=q, learning_rate=0.05, max_iter=300, max_depth=4, random_state=0)
    return pd.Series(m.fit(X[fit_rows], y[fit_rows]).predict(X[test_rows]), index=X.index[test_rows])

low, high = fit_quantile(0.1, test_y.index[0]), fit_quantile(0.9, test_y.index[0])
inside = ((test_y >= low) & (test_y <= high)).mean()

ax = test_y.plot(label="actual", figsize=(9, 3.2), marker="o", ms=3)
pred.plot(ax=ax, label="forecast")
ax.fill_between(low.index, low, high, alpha=0.2, label="10th to 90th percentile")
ax.set_xlabel("")
ax.legend()
print(f"{inside:.0%} of actual days fell inside the 80% band; total units: forecast {pred.sum():,.0f}, high scenario {high.sum():,.0f}, actual {test_y.sum():,.0f}")
`} />

Always check coverage on held-out data, as printed above. If clearly fewer than 80% of days land inside an "80% band", the band is too narrow: say so, or widen it using the errors from your backtest. The message for Sam: *"Plan for about X units over the four weeks; staff for up to Y on peak days."*

<Lab title="Forecast many series with a dedicated library" time="20 min">

At work you rarely forecast one series; you forecast hundreds (every category, every warehouse). Libraries such as **statsforecast** fit and backtest classical models across many series in one call:

```python
import pandas as pd
from statsforecast import StatsForecast
from statsforecast.models import AutoETS, SeasonalNaive

df = (
    pd.read_parquet("data/daily_demand.parquet")
    .rename(columns={"category": "unique_id", "date": "ds", "units": "y"})[["unique_id", "ds", "y"]]
)
# regular daily index per series first (lesson step 1), e.g. with df.set_index("ds").groupby("unique_id")["y"].apply(lambda s: s.asfreq("D").interpolate())

sf = StatsForecast(models=[SeasonalNaive(season_length=7), AutoETS(season_length=7)], freq="D")
cv = sf.cross_validation(df=df, h=28, step_size=28, n_windows=6)   # rolling-origin backtest for all series
print(cv.head())
```
