## A worked ticket

> **Priya (Marketing):** How many orders and how much revenue did each device bring in last December?

Two decisions hide in that sentence. *Revenue* at Bramble means **completed** orders only (cancelled and refunded orders bring in nothing). And "December" on a timestamp column needs a **half-open interval**: `>= "2024-12-01"` and `< "2025-01-01"`.

<PyCell code={`
december = orders[
    (orders["status"] == "completed")
    & (orders["order_ts"] >= "2024-12-01")
    & (orders["order_ts"] < "2025-01-01")
]

(
    december.groupby("device")
    .agg(orders=("order_id", "count"), revenue=("total", "sum"))
    .sort_values("revenue", ascending=False)
)
`} />

> **Gotcha:** `order_ts <= "2024-12-31"` compares against midnight at the *start* of 31 December and silently drops that whole day. Always use `< first day of the next period`.

**2.** The channel lives on `customers`, so join it on. Build `by_channel`: one row per `channel` with columns `orders`, `revenue` and `aov` (average order value), sorted by revenue, highest first.

Pass `validate="many_to_one"` to `merge`. It makes pandas raise if the right-hand key isn't unique, which is the cheapest protection there is against silently duplicated rows.

<PyCell
  code={`
q4_c = q4.merge(customers[["customer_id", "channel"]], on="customer_id", how="left", validate="many_to_one")

by_channel = ...
by_channel
`}
  check={`
_e = _ok.merge(customers[["customer_id", "channel"]], on="customer_id").groupby("channel").agg(orders=("order_id", "count"), revenue=("total", "sum"), aov=("total", "mean")).sort_values("revenue", ascending=False).reset_index()
assert not isinstance(by_channel, type(...)), "replace the ... placeholder"
dsw.same(by_channel, _e, ordered=True)
`}
  hint="`groupby('channel').agg(orders=('order_id', 'count'), revenue=('total', 'sum'), aov=('total', 'mean'))`, then `sort_values`."
  solution={`
q4_c = q4.merge(customers[["customer_id", "channel"]], on="customer_id", how="left", validate="many_to_one")

by_channel = (
    q4_c.groupby("channel")
    .agg(orders=("order_id", "count"), revenue=("total", "sum"), aov=("total", "mean"))

<Lab title="Set up your own environment" time="15 min">

In the modern workplace, Python projects are managed with **uv**: it installs Python itself, resolves dependencies in seconds and records exact versions in a lockfile. Install it from [docs.astral.sh/uv](https://docs.astral.sh/uv/), then:

```bash
uv init bramble-analysis
cd bramble-analysis
uv add pandas duckdb polars pyarrow scikit-learn statsmodels matplotlib jupyterlab
curl -O https://danielfinol.github.io/ds-tutorial/dsw.py
uv run python -c "import dsw; print(dsw.export('data'))"
uv run jupyter lab
```

In a new notebook, re-run the Q4 query with `orders = pd.read_parquet("data/orders.parquet")` and confirm you get the same total as above.

What uv created in `bramble-analysis/`:

- `pyproject.toml` lists the packages the project needs; `uv.lock` records their exact versions. These two files are what you share with your team (by putting them under version control, which lesson 14 covers), so that everyone gets an identical environment.
- `.venv/` is the environment itself: Python plus the installed packages. It belongs to your machine only, it's never shared, and `uv sync` rebuilds it from `uv.lock` at any time.
- `data/` holds the Bramble tables as files.

Can't see `.venv`? On macOS and Linux, names that start with a dot are hidden. Run `ls -a` in the project folder, or press <kbd>Cmd</kbd>+<kbd>Shift</kbd>+<kbd>.</kbd> in the macOS Finder. You may also spot a `.git/` folder and a `.gitignore` file: if git is installed on your machine, `uv init` quietly set the project up as a git repository, already configured to leave `.venv` out. You don't need git yet; lesson 14 shows how to install and use it.

Prefer VS Code? Open the folder, install the Python and Jupyter extensions, and pick `.venv` as the interpreter. Both are common; use whichever your team uses.

</Lab>
